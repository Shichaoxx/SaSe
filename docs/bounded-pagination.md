# 调用预算下的分页评估

这次评估检验两个问题。明确写出“按实际游标继续、遇到空游标就结束”，能否帮助模型在有效页内完成请求？当最终答案不符合 JSON 契约时，模型是否读齐了必需页、是否在答复中提到了正确的记录？

## 实测结果

Qwen2.5-1.5B-Instruct Q4_K_M 在真实 Pi 中完成 36 次运行，服务错误与超时均为零。每次最多发出 6 次模型调用。36 次都读齐了任务要求的页，其中 16 次在请求继续调用工具时用尽预算。其余 20 次给出了最终文本，其中 16 次恰好提及全部目标 ID 各一次，严格 JSON 任务成功数为 0。[四个批次的观测与清单](data/bounded-pagination.json)

| 技能版本 | 策略 | 严格成功 | 用尽预算 | 最终文本中 ID 完全匹配 / 有最终文本 | 工具调用总数 | 总 token（含缓存） |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 原版 | native | 0/6 | 2/6 | 4/4 | 14 | 8,206 |
| 原版 | fixed | 0/6 | 4/6 | 0/2 | 24 | 13,820 |
| 原版 | gated | 0/6 | 2/6 | 4/4 | 14 | 8,464 |
| 候选 | native | 0/6 | 2/6 | 4/4 | 14 | 8,206 |
| 候选 | fixed | 0/6 | 4/6 | 0/2 | 24 | 15,002 |
| 候选 | gated | 0/6 | 2/6 | 4/4 | 14 | 8,584 |

在两个“只取首页”的 Fixed 运行中，使用原技能时，模型依次请求第 1 至 5 页。使用候选技能时，模型连续五次请求第 1 页。两个版本均在第六次模型调用后停止。Gated 在这两个任务上都跳过了技能，模型各读取了一次首页，答复中提及的 ID 完全匹配，但未按要求输出 JSON。

候选版本在 Fixed 与 Gated 各六个匹配任务中均未提高严格成功率，也未减少预算终止次数。与原版相比，每次 Fixed 运行平均多用 197 个总 token，每次 Gated 运行多用 20 个。项目继续使用原分页技能，候选版本保留为可复核的实验样例。这些结果覆盖同一个量化模型和六个合成任务。

## 运行配置

Pi 1.6.0，llama.cpp b12726，8192 上下文，单推理槽，Jinja 工具模板，温度 0，服务端默认生成上限 512。模型权重 SHA-256 与原始试验一致。公开观测保留首页决策、曝光、页访问、格式与合成 ID 统计。本地批次账本保存完整决策序列。

## 比较条件

- 基线使用原有分页技能。候选技能增加首页任务的停止条件、游标失效或重复时的处理，以及按用户指定格式返回结果的说明。两份技能同名，内容哈希区分版本。每批只选用其中一份，Native、Fixed、Gated 保持原有定义。[基线技能](../examples/paginate/SKILL.md) · [候选技能](../examples/candidates/cursor-stop/paginate/SKILL.md)
- 每次运行最多允许 6 次模型调用。一次成功的两页读取可以在 3 次调用内完成。预算在三组中相同。用尽预算仍要求调用工具的任务按失败评分。服务错误和超时继续列为缺失。一次模型调用可能请求多个工具，二者分别计数。
- 每类任务各一个。种子 42 用于复查原始问题，种子 43 使用新生成的记录与布局。种子 42 先运行基线技能批次，种子 43 先运行候选技能批次。同一种子下两批的任务与组内顺序完全相同。四批共 36 次运行，其中 12 次 Native 作为重复对照。
- 保留原有严格评分契约。工具读取范围、最终可见文本中的合成 ID、JSON 格式、预算终止次数及 token 用量用于解释结果。首轮无调用数上限的试验另行保留。技能版本之间的对照使用同一预算。[原始试验](pagination-pilot.md)

在仓库根目录选择技能与预算后运行。将 MODEL 替换为本地服务提供的模型名。

```sh
npm run evaluate -- --model MODEL --base-url http://127.0.0.1:8080/v1 \
  --seed 43 --max-model-calls 6 \
  --skill examples/candidates/cursor-stop/paginate/SKILL.md
```

批次目录保留技能副本、版本哈希、预算、逐次观测及账本。候选技能由评估器导入各次试验的独立工作区，日常项目可自行审阅和批准版本。
