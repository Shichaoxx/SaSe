# Observe & Recall 验证报告

本报告覆盖 Pi 1.6.0 的 `openai-completions` 接口。测试使用真实 Pi 扩展加载器、工具循环和 HTTP 客户端。一个回环地址上的确定性 provider 返回工具调用，并在接收端核对完整技能补丁。这个设置可以验证分配、投递、曝光和重试，技能对模型任务成功率的影响需要另设对照实验。

## 复现

在仓库根目录安装锁定依赖，然后运行验收与性能测试。依赖就绪后，所有测试都使用本地资源。故障测试依赖 POSIX 进程信号。

```sh
npm ci
make test
make bench
```

`make test` 包括 12 项 Python 测试、5 项 Node.js 测试和下表的 7 个 Pi 集成场景。要检查从分页事件到 provider 回执的完整记录，单独执行以下命令。演示结束时会打印账本的查询命令。

```sh
npm run demo -- --case=all-more --keep-evidence
```

## 功能与故障验证

测试覆盖三个不同的目标与反馈组合。获取全部数据且仍有下一页时注入 `paginate`。将反馈改为末页，或将目标改为只取第一页，均会跳过。每种情况都核对状态快照、源事件引用、技能版本和决策理由。

| 场景 | HTTP 请求 | 含冻结补丁的请求 | 验证结果 |
| --- | ---: | ---: | --- |
| 获取全部，有下一页，Pi 重建上下文 | 4 | 2 | 同一逻辑调用只分配一次。503 响应前后的两次请求各含一份相同补丁 |
| 获取全部，已到末页 | 2 | 0 | 决策理由为 `last_page` |
| 只取首页，仍有下一页 | 2 | 0 | 决策理由为 `first_page_only` |
| 获取全部，有下一页，HTTP 客户端重试 | 4 | 2 | 关闭宿主级重试后，客户端两次发送相同的冻结补丁 |
| 禁用扩展 | 3 | 0 | Pi 完成分页任务，账本中没有决策 |
| 终止已响应的 Core 进程 | 3 | 0 | Pi 完成分页任务并报告降级，账本中没有虚假的投递回执 |
| 暂停 Core 触发超时，然后恢复 | 3 | 0 | Pi 完成分页任务，迟到响应未进入后续请求 |

表中的 HTTP 请求数包含初始模型调用及所有重试。脚本逐次核对页面序列和终局文本，并分别记录近端与远端结果。七个场景中与预期序列无关的模型调用数为零，Pi 在禁用扩展、进程终止和超时测试中均完成任务。测试还检查了 Pi 会话文件中没有补丁标记、SaSe 数据库中没有合成工具行的内容标记。[集成测试与 provider](../scripts/pi-demo.mjs)

运行 `all-more` 时，测试调用 `pi install --local` 注册扩展，由真实 Pi 从项目设置加载。配套测试验证项目级卸载、分支隔离、同一次调用重复构建上下文、并行工具结果归属、事件重放、决策落库后的进程恢复，以及 IPC 超时后的响应配对。[核心与安装测试](../tests/) · [Pi 适配器与边界测试](../plugins/pi/)

## 决策延迟

参考测量的运行环境为 macOS、Python 3.12.13、SQLite 3.51.2 和 Node.js 26.0.0。基准复用 Pi 插件的 IPC 客户端，对常驻 Core 和新的 SQLite 账本逐次发送 `decide`。每个场景预热 10 次，随后测量 100 个不同逻辑调用。P95 为升序样本的第 95 个值。计时包含序列化、IPC、投影、技能选择及 SQLite 提交，止于客户端收到决策。[基准程序](../scripts/benchmark.mjs)

| 场景 | 热态 P95 |
| --- | ---: |
| 获取全部，有下一页 | 0.303 ms |
| 获取全部，已到末页 | 0.320 ms |
| 只取首页，仍有下一页 | 0.310 ms |

同次运行从启动子进程到第一次 `inspect` 响应耗时 **60.951 ms**，其中包含新数据库初始化。三组热态 P95 均低于 100 ms 的基准目标。Pi 适配器的默认同步请求截止时间为 200 ms，可通过 `SASE_TIMEOUT_MS` 设置。不同并发度、存储条件与宿主版本需分别测量。
