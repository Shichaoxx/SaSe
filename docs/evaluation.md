# 分页任务配对评估

这项评估比较同一个模型在相同分页任务上的三种运行方式。Native 测量宿主自行完成任务的表现，Fixed 测量在固定时机提供技能的效果，Gated 测量根据目标与工具反馈选择是否提供技能的效果。三组均使用 Pi 1.6.0、同一个分页工具、相同任务指令和回答格式。每次运行都使用独立会话。

## 运行一个批次

在仓库根目录安装依赖。先使用本地确定性 provider 检查模型调用、工具执行、曝光记录与评分是否连通。

```sh
npm ci
npm run evaluate -- --fixture
```

要测量一个模型，请使用支持流式 Chat Completions 和工具调用的服务，将 `MODEL` 替换为端点提供的模型 ID。下例生成三种任务各一个，每个任务分别运行三组，共九次。将 `NEW_DIR` 换成尚未创建的输出目录。

```sh
npm run evaluate -- --model MODEL --base-url http://127.0.0.1:8080/v1 \
  --seed 42 --per-type 1 --output NEW_DIR
```

- `--seed` 决定合成数据、任务执行顺序及每个任务内的策略顺序。模型的温度设为 0。重跑时应记录实际模型版本和服务配置。
- `--per-type N` 生成每类 N 个任务，总计 9N 次运行。增加 N 会同时增加模型调用与 token 消耗。
- `--timeout` 设定单次运行的秒数，默认 90。省略 `--output` 时会在 `evaluation-runs/` 下创建独立批次目录。
- 远程服务使用 HTTPS，并通过 `--key-env SASE_EVAL_API_KEY` 指定已经设置密钥的环境变量名。回环地址支持 HTTP，无需鉴权的本地服务可以省略该参数。服务报告 token 用量时，评估器会累计每次模型调用的用量。

确定性 provider 按预设流程翻页并生成答案，适合重复检查评估工具。用于比较模型任务收益的批次应选择 `--model`。[批次入口](../sase/evaluate.py) · [Pi 运行器](../scripts/eval-runner.mjs)

## 比较条件

| 评估组 | 首次成功读取第一页后的行为 | 证据来源 |
| --- | --- | --- |
| `native` | 由 Pi 和模型继续执行，未加载 SaSe 适配器 | Pi 的工具执行和最终答复 |
| `fixed` | 在下一次模型调用提供一次冻结的分页技能，包括目标已完成的情况 | 分配、版本和回执进入本地账本 |
| `gated` | 在同一个机会检查目标与 `has_next`。只有要求全部数据且仍有下一页时才提供同一版本的技能 | 分配、跳过理由、版本和回执进入本地账本 |

Fixed 和 Gated 都只有一次干预机会，要求页号与分页反馈能归属到同一次成功的首页工具调用。Gated 缺乏继续分页的依据时，该机会以 `skip` 结束。重复读取首页不会触发第二次分配。此限制由评估运行器显式启用。日常 Pi 扩展继续在每次模型调用前依据当时的状态检索。[评估策略实现](../sase/core.py)

| 任务类型 | 任务中的页 | 需要读取并返回的记录 |
| --- | --- | --- |
| `all-more` | 两页 | 两页的全部记录 |
| `first-more` | 两页 | 仅第一页 |
| `all-last` | 一页 | 该页全部记录 |

同一组任务共享首页数据，三种策略面对相同的页内容与目标。模型只能通过 `sase_page` 读取记录，最终回答须为一个含 `ids` 字符串数组的 JSON 对象。数组顺序不影响评分。

## 评分与分母

只有实际读完所有要求的页、每条目标记录恰好返回一次、且读取范围符合请求，任务才算成功。评分器检查实际读取和最终 ID。完整回答的格式错误、遗漏或重复 ID、返回多余 ID、访问无效页或越过用户要求的范围，均记为失败。超时、服务错误和执行轨迹缺失单列为缺失。[评分器](../sase/evaluation.py)

| 指标 | 计算方法 |
| --- | --- |
| 成功率 | 已评分成功数除以已评分运行数。另报告以全部计划运行数为分母的上下界，分别把所有缺失视作失败或成功。这个范围表达缺失带来的不确定性。 |
| 工具调用与额外调用 | 只对已评分运行计算均值。额外调用数等于工具调用总数减去已成功读取的不同必需页数。重复读取必需页增加成本，单独出现时仍可判成功。 |
| 无效页与超目标读取 | 不存在的页或无法解释的工具调用计入无效页。页实际存在但超出用户请求范围，计入超目标读取，例如只要首页却读取第二页。 |
| 配对胜、平、负 | 仅比较同一个任务上两侧均已评分的结果。胜是比较组成功而基线失败，负是反向情形。成功率差为胜数减负数，再除以完整配对数，以百分点表示。 |
| 配对 token 差 | 在完整配对中，再选取双方用量均可获得的任务。用比较组总 token 减基线总 token 后取均值，同时报告有效配对数。 |

## 复核一次失败

先打开批次的 `report.md` 查看任务类型、策略、缺失数量和完整配对数，再从“失败与缺失”表定位一次运行。

| 产物 | 可核对的内容 |
| --- | --- |
| `manifest.json` | 运行模式、种子、任务定义、策略执行顺序、模型标识和源码指纹 |
| `observations.json` | 实际读取的页、最终 ID、模型用量、错误类别、决策 ID 与曝光位置。已知的合成记录保留原 ID，集合外的任意输出字符串保存为摘要 |
| `summary.json`、`report.md` | 分任务类型与整体的汇总、配对差值，以及失败或缺失的原因和引用 |
| `ledger.sqlite3` | Fixed 和 Gated 的冻结状态、技能版本、投递回执及曝光观察。观测中的 `trace_ref` 是查询此账本时使用的工作区 |

以下命令查询示例批次中的 Gated 首页限定任务。可加 `--decision-id` 只查看某个决定。

```sh
python3 -m sase inspect --db NEW_DIR/ledger.sqlite3 \
  --workspace pagination-v1-42-0000-first-more-gated
```

`inject` 表示 Core 已分配技能。位于 `request_payload` 的 `observed` 回执表示适配器在请求构造阶段看到了完整补丁。任务成功还需要独立核对返回的记录和实际页访问。解读小批次结果时，应同时报告模型、任务种子、完整配对数与缺失情况。[协议与重试语义](protocol.md)

一次使用 Qwen2.5-1.5B-Instruct 的真实模型运行展示了成功率、工具调用和 token 成本如何分别解读。[分页试验结果](pagination-pilot.md)
